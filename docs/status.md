## Current Read

As of 2026-09-01 the app is a complete local-first planning instrument in daily curatorial use: MVP 1 and MVP 2 are shipped, MVP 3 (packages, exports, sharing, polish) is most of the way through, and the codebase just came out of a refactor pass with every check green (tsc, 3,729 vitest, 60 Playwright tests, chunk-graph assertion). What exists today, by area:

- **Rooms and architecture.** Fast rectangle path plus polygon drawing/reshape (vertex drag, wall split/delete, wall slide, typed wall lengths with start/end anchors); free-standing partitions (schema v3) with four-sided clearances, centering, elevation profiles and spacing-neighbor behavior; doors, windows and blocked zones; a door or window on a boundary shared by two rooms is one physical opening with two synchronized faces (scoped atomic reconciliation, named issues with guarded inspector resolutions, no connection dropdown); optional hinged door leaves; explicit full-span open walls; floor and wall display cases (schema v4); wall shelves that carry the works standing on them (schema v7); wall-text panels.
- **Works and placement.** Global artwork library plus per-project checklist membership; image intake with thumbnail/display tiers and content-hash duplicate detection; an Import wizard for images, spreadsheet metadata, or both; known/approximate/unknown dimensions; mat and frame with finish shading; four display types (wall work / wall projection / box monitor / sculpture) derived from a free-text Medium combobox with an explicit override; wall works with depth render as protruding boxes; floor works are rotatable, suspendable boxes with per-face images, back-to-back pairing, and a Wall|Floor Type toggle that converts the placement; a floor work can stand on an attached pedestal or plinth, optionally under a plexi bonnet, chosen through one "Stands on" select. Snapping is one pure engine (shelf tops, centerline, neighbors, floor, grid, partition midpoints) with hysteresis and collision stays separate; multi-select, grouping, equal distribution, centering in bay/on wall, keyboard nudge, neighbor-aware dimension lines, and the measurement tool (slice 1) sit on top.
- **Views.** Plan and elevation are SVG projections of `buildPlanScene`/`buildElevationScene`; 3D is a derived R3F scene (`scene3d.ts`) with room shells, textured works, true shared openings, cases, partitions, hinged leaves, CRT monitors and suspension wires. 3D is editable by drop-to-place, arrow nudge and pointer drag (no barriers and no snapping there except seating a wall work on a shelf; elevation and the inspector remain the precision surfaces; gizmos stay out of scope). Navigation: cursor-directed dolly, WASD, focus flights, touch pan, hand tool + zoom chips. Saved views are project data with an out-of-project thumbnail cache. Checklist sort and group-by-artist are stored on the project.
- **Exports.** PNG snapshots of any view; a multi-page PDF (overview, room plans, wall elevations, saved-view 3D pages) with automatic dimension lines and embedded fonts; a PDF checklist; a spreadsheet checklist (xlsx/CSV, optional images folder) whose headers round-trip through the import wizard; `.sightlines` packages in three image tiers. Exports consume the same scene builders the canvas renders from, so print cannot drift from screen.
- **Storage and cloud.** IndexedDB behind repository interfaces; schema-versioned documents with migration chains; silent last-5 snapshots; cross-tab refresh over `BroadcastChannel`; Dropbox (App Folder, PKCE, no Sightlines backend) for versioned backups, one-way share links, a cloud project browser, and canonical single-user cross-device sync with rev-conditional writes and whole-project conflict choices — all folded into one "Dropbox" row in the save-status popover. Sync stages 3–4 (share-link management, content-addressed cloud assets) are designed, not built.
- **Trust surfaces.** The Phase 2 privacy boundary is live: a consent-first, device-local preference defaults both categories off, a neutral first-use notice records an explicit choice, Settings exposes independent usage-analytics and crash-report controls, and a typed gateway rejects unlisted events. Analytics run through manually loaded Cloudflare Web Analytics plus a same-origin Workers Analytics Engine endpoint only after usage permission; the allowlist covers app open, project creation, artwork import, view open, PDF export, package import, cloud project open, and Dropbox connection outcomes, and excludes content, free-form values, request metadata and identifiers. Cloudflare retains unsampled Web Analytics for seven days (then aggregates, six months of dashboard access) and Analytics Engine events for three months. Sentry Uptime watches the public app (failure/recovery notifications exercised 2026-07-19); the Sentry browser error SDK stays deferred and inert even though the crash-report preference exists. Static About/Privacy/Security/IT pages and crawler/security metadata live under `public/`; production CSP carries `blob:` in `connect-src` so snapshot export works. Deployed to app.sightlines.art on Cloudflare Workers with a temporary Vercel mirror (`docs/deployment.md`).


The frozen 3D spec (`docs/archive/3d-preview-spec.md`) still says "no 3D editing"; that rule was superseded on 2026-08-11 (drop + nudge) and 2026-08-28 (pointer drag) — see `docs/archive/interaction-improvements-2026-08.md` §4 and `docs/archive/feedback-round-2026-08-28.md`.

## Onboarding & Feedback (as of 2026-07-19; the feedback-round bullet added 2026-09-01)

The app is dogfooded by its author, a working curator, on real exhibitions — feature work is driven by real layout needs encountered along the way, not speculative roadmap items. Wider sharing is starting deliberately gradually:

- **Non-curators** (partner, family) have seen the app first, as comprehension testers — watching where a cold user stalls surfaces missing labels/tooltips/onboarding beats before anything else does.
- **Curator friends** are next: screen-recorded sessions using both a sample project and their own real working files. Their spreadsheets/images double as a real-world import-robustness corpus (messier than the Rijksmuseum/AIC fixtures) — files that import wrong or confusingly are worth keeping as new test fixtures. The storage-safety net (cloud backup + snapshot recovery, Near-Term Order #1) shipped 2026-07-19, so this tier is technically unblocked — starting it is the user's judgment call, since it puts real files from other people's machines through the flow for the first time. Note the Dropbox rollout staging in `docs/cloud-backup-providers.md`: keep the curator-friends pilot to ~5–20 linked Dropbox accounts, and have production-approval materials ready before ~30–40 cumulative links.
- **A supervisor demo** is planned during an upcoming work trip, on a real shared exhibition the two are co-curating — currently laid out in PowerPoint, the tool's actual real-world competitor. Watching what she reflexively tries to do that has no equivalent in Sightlines is high-value signal.
- **First outside feedback round (2026-08-28)**: `docs/archive/feedback-round-2026-08-28.md` records the first batch driven by a colleague's use plus the curator wishlist — it surfaced a real defect (Windows saved exports without extensions), a discoverability failure (the 3D-views section of the PDF dialog was never found), and two feature asks (CRT monitors, 3D hand/zoom controls). Cold-user passes find defects, not only polish.
- **Guided onboarding** (planned, not yet built): a sample project with preloaded images and a basic layout, walking a new user through hanging one room, arranging art, and adding a second room — skippable straight to a blank project. Should teach the Insert-decorates/Draw-creates grammar, not just a click sequence, and the sample project must stay clearly disposable/regenerable per the "boot never silently substitutes a fresh sample" rule (plan.md §8).


## Known Follow-Ups

Open items carried out of shipped rounds. None is blocking. Cross one off here when it ships.

**Product gaps**
- PDF plan pages draw a suspended board exactly like a floor-resting one: no height-off-floor callout, no facing information, and no indication of which faces carry the image (elevation pages do draw the suspended ghost with wires).
- Plan and elevation draw only the support's outline for floor works, so a 7′ board carrying a 5′ work reads as a 7′ work; drawing the work's extent inside the outline would make the distinction legible where a preparator reads it.
- Elevation suspension wires end at the viewed wall's top while 3D wires go to room height — the two disagree on where the rigging terminates.
- Cross-tab refresh covers only the open document and the artwork library; project-manager writes to a project that is not open (rename-by-id, delete) do not announce, and the saved-projects list does not refresh across tabs.
- The export preview still draws windows and blocked zones with a coarse corner-to-corner diagonal where the PDF draws mullions and hatch.
- Deferred 3D editing parity: wall↔floor conversion mid-drag, group drag, touch drag.
- Rider-aware 3D shelf drag: a shelf is selectable in 3D but deliberately not draggable, so moving a slab out from under its works is only possible in plan, elevation or the inspector.
- Overlapping door/window holes on one wall triangulate with minor artifacts (`docs/archive/3d-preview-spec.md` §10); the domain already flags overlapping placements for review.
- Eye height uses `project.defaultCenterlineHeightMm` as a proxy; add a per-project `eyeHeightMm` if users trip on it.
- The Sentry browser error SDK is deferred and inert; the crash-report preference exists so the consent surface is complete, but nothing ships crash reports yet.

**Device verification still open**
- Elevation pinch-during-measurement on a real iPad in Mobile Safari (the Chromium CDP trusted-touch regression in `e2e/elevation-pinch-measurement.spec.ts` passes).
- Tablet leg of the renderer benchmark (Near-Term Order #4).

**Code debts (deliberately deferred, revisit on demand)**
- Display-kind descriptor table (when a fifth display kind lands); `commitPackageImport` split; `updateArtwork` rebake extraction; widen `ProjectSyncMeta.provider` from the `"dropbox"` literal when a second provider is planned.
- `store/types.ts` for `AppState`/`EditExtras` to break the type-only store⇄slice import cycle.
- `floorAlign` context helper in PlanView (three repetitions — extract on the fourth use); component render tests for case/wall-text components; unused shadcn primitive exports.
- Face picker uses `Toggle`s where DESIGN.md's stricter reading says `Checkbox` (per-face flags are data, not modes) — deliberate for now, worth re-reading against the rule.
- `elevation/GroupDimensionLines` imports `../plan/labelStagger` (cross-feature edge — candidate for `shared/` if it grows). Export scale/JPEG-quality constants are intentionally duplicated between `captureSnapshot.ts` and `SnapshotStage.tsx` per export-spec §10.4 — do not consolidate. The >900 kB pdf chunk build warning is pre-existing and acknowledged.

## Deferred

Curved walls, 3D transform gizmos and snapping/barriers in 3D (drop, nudge and pointer drag shipped in August; precision stays in elevation and the inspector), hosted accounts/collaboration, and registrar-level collection management remain out of the near-term product scope.

Deliberately skipped in the 2D zoom/pan MVP (revisit only on demand): ⌘+/⌘− zoom shortcuts (conflict with browser page zoom), double-click-to-fit, pan-distance clamping, and viewport persistence across sessions.
