## Current Read

As of 2026-09-01 the app is a complete local-first planning instrument in daily curatorial use: MVP 1 and MVP 2 are shipped, MVP 3 (packages, exports, sharing, polish) is most of the way through, and the codebase just came out of a refactor pass with every check green (tsc, 3,729 vitest, 60 Playwright tests, chunk-graph assertion). What exists today, by area:

- **Rooms and architecture.** Fast rectangle path plus polygon drawing/reshape (vertex drag, wall split/delete, wall slide, typed wall lengths with start/end anchors); free-standing partitions (schema v3) with four-sided clearances, centering, elevation profiles and spacing-neighbor behavior; doors, windows and blocked zones; a door or window on a boundary shared by two rooms is one physical opening with two synchronized faces (scoped atomic reconciliation, named issues with guarded inspector resolutions, no connection dropdown); optional hinged door leaves; explicit full-span open walls; floor and wall display cases (schema v4); wall-text panels.
- **Works and placement.** Global artwork library plus per-project checklist membership; image intake with thumbnail/display tiers and content-hash duplicate detection; an Import wizard for images, spreadsheet metadata, or both; known/approximate/unknown dimensions; mat and frame with finish shading; four display types (wall work / wall projection / box monitor / sculpture) derived from a free-text Medium combobox with an explicit override; wall works with depth render as protruding boxes; floor works are rotatable, suspendable boxes with per-face images, back-to-back pairing, and a Wall|Floor Type toggle that converts the placement. Snapping is one pure engine (centerline, neighbors, floor, grid, partition midpoints) with hysteresis and collision stays separate; multi-select, grouping, equal distribution, centering in bay/on wall, keyboard nudge, neighbor-aware dimension lines, and the measurement tool (slice 1) sit on top.
- **Views.** Plan and elevation are SVG projections of `buildPlanScene`/`buildElevationScene`; 3D is a derived R3F scene (`scene3d.ts`) with room shells, textured works, true shared openings, cases, partitions, hinged leaves, CRT monitors and suspension wires. 3D is editable by drop-to-place, arrow nudge and pointer drag (no snapping or barriers there; elevation and the inspector remain the precision surfaces; gizmos stay out of scope). Navigation: cursor-directed dolly, WASD, focus flights, touch pan, hand tool + zoom chips. Saved views are project data with an out-of-project thumbnail cache. Checklist sort and group-by-artist are stored on the project.
- **Exports.** PNG snapshots of any view; a multi-page PDF (overview, room plans, wall elevations, saved-view 3D pages) with automatic dimension lines and embedded fonts; a PDF checklist; a spreadsheet checklist (xlsx/CSV, optional images folder) whose headers round-trip through the import wizard; `.sightlines` packages in three image tiers. Exports consume the same scene builders the canvas renders from, so print cannot drift from screen.
- **Storage and cloud.** IndexedDB behind repository interfaces; schema-versioned documents with migration chains; silent last-5 snapshots; cross-tab refresh over `BroadcastChannel`; Dropbox (App Folder, PKCE, no Sightlines backend) for versioned backups, one-way share links, a cloud project browser, and canonical single-user cross-device sync with rev-conditional writes and whole-project conflict choices — all folded into one "Dropbox" row in the save-status popover. Sync stages 3–4 (share-link management, content-addressed cloud assets) are designed, not built.
- **Trust surfaces.** The Phase 2 privacy boundary is live: a consent-first, device-local preference defaults both categories off, a neutral first-use notice records an explicit choice, Settings exposes independent usage-analytics and crash-report controls, and a typed gateway rejects unlisted events. Analytics run through manually loaded Cloudflare Web Analytics plus a same-origin Workers Analytics Engine endpoint only after usage permission; the allowlist covers app open, project creation, artwork import, view open, PDF export, package import, cloud project open, and Dropbox connection outcomes, and excludes content, free-form values, request metadata and identifiers. Cloudflare retains unsampled Web Analytics for seven days (then aggregates, six months of dashboard access) and Analytics Engine events for three months. Sentry Uptime watches the public app (failure/recovery notifications exercised 2026-07-19); the Sentry browser error SDK stays deferred and inert even though the crash-report preference exists. Static About/Privacy/Security/IT pages and crawler/security metadata live under `public/`; production CSP carries `blob:` in `connect-src` so snapshot export works. Deployed to app.sightlines.art on Cloudflare Workers with a temporary Vercel mirror (`docs/deployment.md`).

The frozen 3D spec (`docs/archive/3d-preview-spec.md`) still says "no 3D editing"; that rule was superseded on 2026-08-11 (drop + nudge) and 2026-08-28 (pointer drag) — see `docs/interaction-improvements-2026-08.md` §4 and the Feedback Round section below.

## Hinged Doors (shipped 2026-08-09)

An optional hinged leaf on a door, per `docs/plan.md` §4.2. Openings stay what they were: `kind: "door"` is still a void, and the new `leaf` field is absent by default, so every existing project is a project of plain doorways and the default path renders byte-identically in all three views. Built across five concurrent slices and committed 2026-08-08 (`df4af9e`, `cec3b6b`, `0bff49b`).

- **Model**: `DoorWallObject` split out of the connectable-opening union so only a door can carry `leaf` — the window branch spells the prohibition as `z.never().optional()`, because zod strips unknown keys by default and "omit it from the schema" would have silently dropped the field instead of rejecting it. Purely additive optional field, so **no schema-version bump**.
- **Coordinates**: both handing flags are stated against the wall's authored `start -> end`, so no renderer consults room winding. The one place winding matters is 3D, where `deriveRoom` reverses panels for clockwise rooms and the hinge must be remapped to panel-local x — verified against a seeded clockwise room, which is where this feature was most likely to be quietly wrong.
- **Pairing**: mirroring is gated on `areSharedBoundaryWalls`, matching what position edits already do, so legacy pairs on unrelated walls keep independent leaves. Adoption resolves conflict by **hinged wins**, never by whichever id sorts first — the sort-order rule would silently erase the only leaf in a pair.
- **Surfaces**: one shared pure glyph module (`domain/geometry/doorGlyphs.ts`, the `caseGlyphs.ts` pattern) feeds canvas, PDF and the export preview, so the three cannot drift. The plan swing arc is the only glyph that paints outside its own rect; it is pointer-transparent, and interaction bounds are deliberately unchanged while **paint/export** bounds grew to include it (an outward 915 mm swing was otherwise cropped by the 300 mm room-page margin).
- **Found and fixed en route**: export-preview plan pages had been vertically **mirrored** relative to the printed PDF since the preview shipped (`cec13cba`, 2026-07-21). `planTransform` copied `createPlanTransform`'s `(maxYMm - yMm)` flip, which is correct only for pdf-lib's y-UP page space and inverts in the preview's y-DOWN SVG. Invisible while plan glyphs were symmetric; the swing arc is the first strongly handed one. Fixed and pinned by `ExportPdfPreview.test.ts`, which asserts orientation rather than arithmetic. Fixing it then exposed a second defect it had been masking: `planDimensionMarks` compared a screen-space normal against a world-space outward vector and hand-corrected the mismatch with a `-outWorldY`, so un-mirroring the page flipped the north and south dimension hints *inside* the room while east and west stayed right (only the x term was untouched). Now both sides of that comparison are computed in screen space via the transform itself, so it holds under any future axis convention rather than encoding this one.
- **Verification**: tsc + 2,732 vitest + `npm run build` + 36 e2e green, plus a headless real-app pass covering the default-doorway regression, clockwise rooms, shared vs legacy pairs, narrow/short door clamping, undo and reload, and PDF page-crop on outward swings. New `e2e/hinged-doors.spec.ts` proves the arc is pointer-transparent by driving a real drag on the wall handle underneath it and asserting the room moved and the door did not.
- **The 3D leaf is white with a drawn edge, and the edge is the load-bearing part.** Measured face contrast against the wall is 1.19 on the lit side but **1.08 on the shade side** (a 9/255 step) — over there the door is legible only because of its `#b6bcc2` outline (1.64 against the wall). The first cut drew that outline on the leaf's exact box, so line and surface fought for the depth buffer and 27.8% of the jamb-side scanlines lost the line entirely; `DOOR_LEAF_EDGE_OUTSET_MM` (3mm of clearance per side) takes that to 0%. Any future change that suppresses or thins this edge should be weighed against the shade-side number — it is a single point of failure by design.
- **Known and intentional**: "Flip swing" has no visible effect in 3D — a shut leaf is symmetric about the wall plane, so only the hinge moves anything there. Swing clearance is advisory: nothing about the arc blocks or warns on placement.
- **Not done**: the preview still draws windows and blocked zones with a coarse corner-to-corner diagonal where the PDF draws mullions and hatch (pre-existing, deliberately left).

## Freestanding / Suspended Projection Board (shipped 2026-08-10)

A video projection surface — an MDF panel hung from ceiling wires, angled to the wall, hovering above the floor. Modelled by **extending the existing floor artwork** rather than inventing an object kind: the work *is* the board. `ArtworkFloorObject` was already a rotatable box with a texture; what was missing was a lift, wires, and any way to reach an angle. Committed in `89219ac` (suspension) and `bf2b6eb` (per-face images).

- **`baseHeightMm`** — the bottom edge's height above the floor, optional and additive, so **no schema bump**. Read the TRAP on `FloorObjectBase`: it is not `wallYMm`. A blocked zone deliberately ignores it (a floor-*area* annotation has no volume to hover), and a display case stands on its own legs.
- **Surfaces**: 3D lifts the box and draws four suspension wires up to the containing room's height (there is no ceiling geometry, so room height is the only vertical datum that exists — a suspended object dragged into the void between rooms draws no wires rather than inventing one); plan gained a rotate handle, a front-face marker, and a minimum hit thickness so a hairline board stays clickable; elevation draws a dashed floating ghost with wires, generalized from the floor-case ghost. Inspector gained Angle, Height off floor, and a **Height** field — `heightMm` is set once at placement and editing the artwork's dimensions deliberately does not rebake it, so a board placed before its dimensions were known had no numeric repair path at all.
- **Per-face image mapping** (`imageFaces` + a six-material box + a six-toggle picker, default front+back). Absent ≠ `[]`: absent means "never chosen" and resolves to the default at read time, empty means every face deliberately off. Both readings round-trip verbatim through a wall capture's `floorMemory`, so a capture cannot rewrite a curatorial choice into the default. The BoxGeometry material-group order is `+x, -x, +y, -y, +z, -z` — not the picker's reading order — and is pinned by a test that reads the real geometry's groups back out of the position buffer.
- **The finding that shaped it**: floor artwork was painted with `meshLambertMaterial` under `AMBIENT_LIGHT_INTENSITY = 2.9`, so every texture was multiplied ~3× and saturated to flat white. **Floor artwork had never visibly shown its image** — not in the canvas, not in saved-view thumbnails, not in PDFs; `ArtworkPlane` had always escaped this per spec §6.2. That is why changing the image default from all-six-faces to front+back needed no migration: there was no prior appearance to preserve. Textured faces are now `MeshBasicMaterial` + `toneMapped: false`; untextured faces stay Lambert so a neutral box still reads as a volume.
- **The support and the work are two different measurements**. The box's Width/Depth/Height size the OBJECT ON THE FLOOR — a projection board, a plinth, a sculpture's bounding volume — and the artwork record's dimensions size the WORK. They coincide at placement (`placeArtworkOnFloor` seeds the box from the work's effective size) and diverge the moment a curator resizes the board. The image is now drawn at the **work's own size, centered on each chosen face**, and shrunk (never distorted) only when the face is too small to hold it. `FloorObject3d` carries `artworkWidthMm`/`artworkHeightMm` per axis, absent when unmeasured, and `floorObjectImageFaces.ts` owns face resolution, sizing, and panel placement. A contextual field hint appears only when the sizes differ and offers **Match size to work** for width and height; depth remains the support's independent thickness.
- **Design correction**: that size note is a quiet `.field-hint` line with an inline tertiary action, not a filled alert card. The compact treatment preserves the touch target while keeping the inspector's flat-panel hierarchy.
- **Verified**: the floor-object slice passed tsc, the current suite is 2,997 vitest tests green, `npm run build` plus the chunk-graph assertion, and a fresh-profile browser pass covering support resizing, work-sized centered image panels, all three view calculations, and live face toggling.
- **Correction worth keeping**: a thin board at 45° projects a **narrower** span onto the wall, not a wider one — a panel foreshortens.

## Cross-Tab Refresh (shipped 2026-08-10)

Every tab held its own full copy of the open project and wrote the **whole** document on every edit, so a second tab left open on the same project would silently overwrite everything the first tab had saved with its stale boot-time copy. Tabs now tell each other when they save.

- **How it works**: `src/app/crossTabSync.ts` wraps one `BroadcastChannel("sightlines-sync")` with two messages — `project-saved` (id + `updatedAt`) and `artworks-saved`. `persist()` announces after every successful document save, and the artwork-library writes announce after re-listing. A tab that hears about a **newer** copy of the project it has open reloads that document from IndexedDB through `setDocument`, and deliberately does not write anything back (no snapshot, no save) — a tab catching up must never become the clobberer.
- **When the reload lands**: an unfocused tab refreshes immediately; a focused one defers (it may be mid-drag) and takes the pending reload on its next `focus`, on the next announcement, or after its own next save. A reload is also held off while a save is in flight or an arrange preview is live. A failed passive reload is logged and dropped — never a toast, never an error state.
- **Advertised trade-offs, not bugs**: two tabs editing the same instant still resolve last-write-wins, and an external reload resets that tab's undo/redo history and selection (a document swap always has — undoing across it would resurrect a document nobody has). This is a refresh, not multiplayer: no locks, no conflict dialogs.
- **Seam**: `AppStoreDeps.crossTabSync` is optional and defaults to a real channel opened lazily on first use; the whole module is inert where `BroadcastChannel` does not exist. Tests inject `createInertCrossTabSync()` or a fake, because a vitest process is one browsing context and every store in it would otherwise hear the others' saves.
- **Known limitation**: only the *open* document and the artwork library refresh. Project-manager writes to a project that is not the open one — rename-by-id, delete — do not announce, so a tab holding that project can still re-save over the rename, or resurrect the deleted project on its next edit. The saved-projects list itself does not refresh across tabs either.

## Checklist View Preferences + Inspector Details Fix (shipped 2026-08-31)

- **Checklist sort and group-by-artist are project data** (`41019b2`, USER DECISION): `project.checklistView?: { sort, groupByArtist }` — optional and additive, no schema bump — so the choice travels with `.sightlines` packages and sync, at the accepted cost that changing it dirties the document. When the field is absent the panel derives a group-show default live (≥2 artists each with ≥2 works ⇒ grouped by artist; blank artists never count); the first explicit choice writes the field and permanently supersedes the heuristic — absence is meaningful, so the schema must never default it in. Search, filter and collapsed groups stay session state; the Export-checklist dialog's own sort is untouched. Pure sort/filter/group helpers live in `checklistViewPreferences.ts`.
- **Details fields showed the previous artwork's values** (was live in production): `TextField` seeds its draft once per mount, and the Details inputs (Object no. / Location / Credit line) were keyed on the field name alone, so a selection change never remounted them and a blur could commit the previous work's object number onto the new one. Keyed on `artwork.id` now, with a regression test in `ArtworkInspector.test.tsx`. The collapsed summary reads the record directly and was always right — verify inspector fields with the section expanded, not from the summary.

## Onboarding & Feedback (as of 2026-07-19; the feedback-round bullet added 2026-09-01)

The app is dogfooded by its author, a working curator, on real exhibitions — feature work is driven by real layout needs encountered along the way, not speculative roadmap items. Wider sharing is starting deliberately gradually:

- **Non-curators** (partner, family) have seen the app first, as comprehension testers — watching where a cold user stalls surfaces missing labels/tooltips/onboarding beats before anything else does.
- **Curator friends** are next: screen-recorded sessions using both a sample project and their own real working files. Their spreadsheets/images double as a real-world import-robustness corpus (messier than the Rijksmuseum/AIC fixtures) — files that import wrong or confusingly are worth keeping as new test fixtures. The storage-safety net (cloud backup + snapshot recovery, Near-Term Order #1) shipped 2026-07-19, so this tier is technically unblocked — starting it is the user's judgment call, since it puts real files from other people's machines through the flow for the first time. Note the Dropbox rollout staging in `docs/cloud-backup-providers.md`: keep the curator-friends pilot to ~5–20 linked Dropbox accounts, and have production-approval materials ready before ~30–40 cumulative links.
- **A supervisor demo** is planned during an upcoming work trip, on a real shared exhibition the two are co-curating — currently laid out in PowerPoint, the tool's actual real-world competitor. Watching what she reflexively tries to do that has no equivalent in Sightlines is high-value signal.
- **First outside feedback round (2026-08-28)**: `docs/feedback-round-2026-08-28.md` records the first batch driven by a colleague's use plus the curator wishlist — it surfaced a real defect (Windows saved exports without extensions), a discoverability failure (the 3D-views section of the PDF dialog was never found), and two feature asks (CRT monitors, 3D hand/zoom controls). Cold-user passes find defects, not only polish.
- **Guided onboarding** (planned, not yet built): a sample project with preloaded images and a basic layout, walking a new user through hanging one room, arranging art, and adding a second room — skippable straight to a blank project.
